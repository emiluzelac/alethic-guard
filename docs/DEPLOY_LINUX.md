# Linux deployment

Use the Ubuntu 24.04 x86-64 host and KVM configuration described in the [runtime matrix](GUARANTEE_MATRIX.md). Install the Ubuntu packages for the supported host.

```sh
sudo apt-get install libvirt-daemon-system libvirt-clients qemu-system-x86 qemu-utils acl python3-venv iproute2 nftables
```

Download the installation archive and `SHA256SUMS` from the [release index](https://github.com/emiluzelac/alethic-guard/tree/release-assets). Run `sha256sum --check SHA256SUMS` in the download directory before extracting the archive. Run the installer from the extracted directory.

```sh
sudo ./packaging/install
```

The installer uses the archive's pinned Python wheels, installs both services, and activates the installed software under `/opt/alethic-guard/current`. On upgrade, contain and terminate active workloads first, then stop both Guard services and run the installer. It reuses existing enrollment, policy, and image directories. Check workload status after restarting the service. For a source build, use `scripts/package-linux OUTPUT_DIRECTORY` from a committed checkout with Rust 1.85 and uv.

## Offline setup

```sh
guard=/opt/alethic-guard/current/venv/bin/alethic-guard
"$guard" profile compile policy/examples/offline-research.yaml --output ./offline-research.json
sudo install -m 0444 ./offline-research.json /etc/alethic-guard/policies/
sudo install -m 0444 ./approved-guest.qcow2 /var/lib/alethic-guard/images/
sudo install -m 0444 ./approved-input.raw /var/lib/alethic-guard/images/
sudo systemctl enable --now alethic-guardd.service
```

Verify the guest image against its publisher or your own image approval before staging it. The JSON policy is generated by the CLI and installed by the trusted operator. Keep policies and images under root-owned directories with read-only file modes. A policy with an empty inputs list creates a VM with a writable private disk alone. The read-only input block device in the sample policy requires an explicit `--input`.

Use the root operator identity for workload commands. Invoke the CLI by its absolute installed path when using sudo and a virtual environment.

```sh
guard=/opt/alethic-guard/current/venv/bin/alethic-guard
sudo "$guard" workload create --profile offline-research --image approved-guest.qcow2 --input approved-input.raw
sudo "$guard" workload start WORKLOAD_ID
sudo "$guard" workload verify WORKLOAD_ID
sudo "$guard" workload contain WORKLOAD_ID
sudo "$guard" workload terminate WORKLOAD_ID
sudo "$guard" evidence export WORKLOAD_ID --format jsonl --output evidence.jsonl
```

libvirt domains are transient. The VM is checked in its paused state before the daemon starts it. Restarting the daemon reconciles outstanding workloads and requires fresh operator release and start. Guest output remains on the launch overlay. Guard stages verified image bytes in a root-owned, content-addressed launch store before starting libvirt. Launches with the same digest reuse that read-only snapshot. The host filesystem must support POSIX ACLs. Guard limits snapshot access to root and the Ubuntu `libvirt-qemu` service account.

## Mediated setup

Keep the guest NIC-free and provide a dedicated route from the Guard host to the collector. Enable IP forwarding for the collector address family. Reserve the UID range 300001–304094, GID 300000, names `aleg*`/`agw*`/`age*`, and subnet ranges `10.254.0.0/18` and `fd42:a1e7::/32` for Guard. The registry dedicates one slot to each mediated enrollment. Restarts and resumes reuse the same slot after verified cleanup.

The installer creates the unprivileged `alethic-guard-controller` account and installs the pinned Alethic kernel wheel. Prepare `/etc/alethic-guard/collector.json` as a root-owned file with mode `0400`. Set the exact HTTPS `target`, approved global unicast `addresses`, `controller_socket` to `/var/lib/alethic-guard/controller/controller.sock`, and `controller_uid` to the numeric result of `id -u alethic-guard-controller`. Omit `gateway` to use the gateway packaged with the installed daemon. For an existing configuration, remove the old `gateway` field when upgrading to this installer. The collector's certificate must cover the configured hostname.

If you supply `ca_file`, install the public CA certificate as root-owned mode `0444` in the policy directory. The unprivileged gateway must be able to traverse its parent directory and read the certificate. Keep the collector's private key on the collector.

```sh
guard=/opt/alethic-guard/current/venv/bin/alethic-guard
"$guard" profile compile policy/examples/allowlisted-api.yaml --mediated-api --output ./broker-lab.json
sudo install -m 0444 ./broker-lab.json /etc/alethic-guard/policies/
sudo install -m 0400 ./collector.json /etc/alethic-guard/collector.json
sudo systemctl enable alethic-guardd.service
sudo systemctl restart alethic-guardd.service
```

The mediated operator socket parent must permit traversal by the dedicated gateway users. The socket is limited by owner/group and peer credentials. Guard creates a second socket at `operator.sock.emergency`, with mode `0600` and a host-root peer check, for `workload cutoff`. During startup, the daemon stops and reconciles any gateway from a previous incarnation before admitting new work. Rotate the root-owned configuration and requalify if you change the collector address, TLS trust, guest image, or backend. See [the lab instructions](../tests/lab/README.md).

## Release evidence staging

Use `policy/examples/release-evidence.yaml` with the mediated setup above. Set its exact HTTPS destination to match the collector configuration and keep the path `/v1/release-evidence`. Compile it with `--mediated-api` and install it as `release-evidence.json` before enrolling the workload with `--profile release-evidence`. Add this property to the collector JSON and install the file as root-owned mode `0400` in a protected directory.

```json
{
  "release_evidence": {
    "record": {
      "artifact_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "commit": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
      "verdict": "pass",
      "version": 1
    },
    "writer_token": "replace_with_a_generated_writer_token"
  }
}
```

The trusted operator sets the 40-character lowercase Git commit, 64-character lowercase artifact SHA-256, and `pass` or `fail` verdict. To request delivery, the guest calls `collector.publish` with its request UUID and `fixture_id` set to `release-evidence`. Guard serializes the approved record and binds its SHA-256 and the destination to the one-use grant.

Run the receiver under a dedicated account that can read its TLS key and token files and write to the SQLite state directory. Use distinct randomly generated URL-safe writer and reader tokens of 32–128 characters. Give the gateway its writer token through the protected collector configuration and give the reader token to the trusted receipt operator.

```sh
/opt/alethic-guard/current/venv/bin/python -I -m alethic_guard.release_evidence_collector \
  --host COLLECTOR_ADDRESS --port 8443 --database /var/lib/collector/evidence.sqlite3 \
  --cert /etc/collector/tls.pem --key /etc/collector/tls.key \
  --writer-token-file /etc/collector/writer-token --reader-token-file /etc/collector/reader-token
```

From the enrolled guest, run `python3 collector.py --fixture release-evidence` with the bundled `guest/tool-client/collector.py`. Keep the reader credential on the operator side.

Use the reader credential over verified TLS to retrieve `GET /v1/release-evidence/<idempotency-key>`. The response contains the key and payload SHA-256. Repeated writes of the same canonical bytes with the same key return the original receipt. Reusing a key with a different record returns HTTP 409. After an ambiguous delivery, read the receipt independently and use the root operator’s `reconcile_receipt` command with the original workload and request IDs. Persist the SQLite file and its sidecars across collector restarts.

## Emergency VM shutdown

Use `sudo /opt/alethic-guard/current/venv/bin/alethic-guard workload emergency-terminate WORKLOAD_ID` when the ordinary operator queue is busy and the managed VM needs to stop. Check `shutdown` separately from `broker_cutoff`. Follow the [revocation and recovery procedure](REVOCATION.md) to reconcile the normal journal and release the fence.
