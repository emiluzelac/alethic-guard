# Lab procedures

Use a disposable Ubuntu 24.04 host or nested KVM guest with a signed cloud image. Install cloud-image utilities, the Guard packages, and tcpdump. Keep the host disconnected from production networks. Prepare a collector namespace with a veth named `guard-observe` on the lab host. The probe fixtures use `198.18.0.2` and `fd42:abcd::2` in that namespace. For the mediated test, assign the fixed lab address aliases used by `qualify.sh` inside the same isolated namespace. Map the collector hostname to the appropriate address in lab DNS. Route these addresses only to the controlled namespace.

Build a synthetic NoCloud input image with `guest/image/make-probe-input SCRATCH OUTPUT [offline|broker]`. Use the signed image and the probe image to enroll the workload under the matching profile. Run the TLS test collector in its own namespace with `collector.py PORT CERT KEY RECEIPT_DIR`. Keep the generated lab key in the lab.

Run `qualify.sh offline ID EVIDENCE_DIR` and `qualify.sh broker ID EVIDENCE_DIR`. The script saves the active XML, interface list, guest serial output, calibrated packet capture, operator reports and evidence journal. Read the packet capture alongside the positive controls and the observed collector receipts. Repeat the broker test with each address family and an independently captured race around host cutoff. Perform the reboot test on the disposable lab host and confirm that workloads still require explicit release.

For the IPv6 cutoff race, use a collector namespace named `guard-race-collector` and route `2602:ff16::2` to it. Use the examples' synthetic collector policy under the name `broker-lab` and enroll two fresh guests using `noble-lab.qcow2` and `broker-probe.img`. Run these from the lab host after starting Guard. Use an unoptimized daemon with the approved full-size image so the handshake case can observe a concurrent enrollment still hashing that image when cutoff completes.

```sh
sudo python3 cutoff-race.py handshake HANDSHAKE_ID HANDSHAKE_EVIDENCE LAB_CERT LAB_KEY --daemon-pid GUARD_DAEMON_PID
sudo python3 cutoff-race.py receipt RECEIPT_ID RECEIPT_EVIDENCE LAB_CERT LAB_KEY
```

The handshake case holds the TLS handshake until cutoff and expects zero receipts. After shutdown, it also verifies that a release already validating the image cannot clear a newer cutoff. The receipt case records the allowed request before cutoff and holds its acknowledgment. It verifies that the outcome remains unknown until the operator reconciles the matching collector receipt. Both cases retain captures, cutoff times, and journal entries. An output-hook counter on the isolated host accounts for TCP resets generated by the host stack when the collector attempts to use a closed flow.

## Transport qualification

Use the disposable nested KVM host for `transport-qualify.py`. Use the same `broker-lab` policy, the `guard-race-collector` namespace, and the dedicated controller installed with the published kernel wheel. Route `2602:ff16::2` and `2602:ff16::3` to the collector namespace. Configure Guard's collector address set to include `2602:ff16::2`, and configure the lab host's system resolver to return only that address for `collector.example` at startup. The DNS case adds `2602:ff16::3` through the lab host's `/etc/hosts` while the guest is running, then restores the file.

The test uses a fixed request ID so a second boot can attempt the same operation. To prepare the synthetic input from the repository root, use a fresh scratch directory and run the following. Stage the resulting image read-only alongside `noble-lab.qcow2` under Guard's approved images directory.

```sh
scratch=$(mktemp -d)
cp guest/image/{make-probe-input,broker_probe.py} "$scratch/"
sed -i 's/str(uuid.uuid4())/"3ef68a9f-6778-46fa-b180-02a907b90651"/' "$scratch/broker_probe.py"
"$scratch/make-probe-input" "$scratch/seed" "$scratch/transport-probe.img" broker
```

Create a lab-only CA and sign `good.pem` for `collector.example` and `wrong-name.pem` for a different hostname. Sign `unknown-ca.pem` for `collector.example` with a second lab CA. Store the corresponding key files next to the certificates. Configure the daemon to trust the first CA and use `/etc/alethic-guard/policies/transport-config.json`. Start it as the transient unit `guard-transport-daemon` with the same state, policy, and operator socket paths as the cutoff lab.

```sh
for test_case in control unknown-ca wrong-name redirect dns-drift disconnect journal-failure gateway-crash daemon-crash; do
    sudo python3 transport-qualify.py "$test_case" "transport-results/$test_case" LAB_CERT_DIR || break
done
```

The cases compare guest results, actual HTTP requests, and TCP flows. The redirect points to a second path on the same trusted TLS endpoint. The journal case aborts effect insertion only for the test workload. The crash cases kill the selected lab process after the collector records the receipt, then repeat the same request ID after explicit release and a fresh guest boot. Run the daemon crash case last because it restarts Guard under a new transient unit.

The packet tests intentionally use synthetic markers. A UDP probe on port 443 verifies the path at the transport layer. It does not exercise a full QUIC handshake.

## Release candidate checks

The scripts in `release-fixtures/` are for the disposable lab. The paused domain fixture substitutes a controlled variation into the input to libvirt, observes the resulting real paused domain, and detects any attempted resume. The interface variant uses `guard-drift0`, an isolated host bridge without IP addresses or uplinks. The mount variant uses an empty, read-only directory. The input variant uses a distinct approved synthetic fixture.

The permit fixture runs under the ordinary per-workload gateway identity and requests authority from the installed daemon and controller without sending collector traffic. The expiry case holds the grant past its ten-second lifetime. The stale case replaces the test controller while the observed grant is still valid. Review the daemon responses, effect counts, and calibrated collector capture together. Use the regular packaged gateway for the positive transport control.

Repeat the install on a fresh Ubuntu image with the tested packages and the published kernel wheel. Verify the systemd-managed offline workload, a real mediated collector receipt, and the CLI journal export. Boot the unsupported-host case with nested virtualization disabled and check that a start request leaves the workload stopped. Use the [release qualification](../../docs/QUALIFICATION.md) for the observations and the [guarantee matrix](../../docs/GUARANTEE_MATRIX.md) for the tested environment.
